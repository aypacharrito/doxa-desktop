# the owner's two reference reels

The first reel proposed nine components: an always-on host, an agent runtime (the speaker recommended Hermes), an AI model, interviewing the owner, persistent memory, reusable skills, connected business/creative tools, messaging access, and a dashboard.

The second proposed a dashboard refreshed each morning, a second brain, an executive assistant that produces morning and evening reviews, a marketing agent that measures social performance, and specialist workers coordinated by one assistant.

These are design references, not proof that a weekend prototype is reliable or that a VPS is always secure. the owner wants the apps themselves to perform useful recurring work without returning to Codex for every run. His priorities are income from California home/auto insurance and English-Spanish interpreting near LA/Orange County, plus improving VYRA content results.

Current implementation: Jarvis Autopilot has owner-configured morning planning, evening task-state review, and a VYRA public performance review. Local models handle personal reviews; the public VYRA report can use OpenAI within Jarvis's $5/month allowance. Tasks save results locally. The VYRA worker collects read-only snapshots every six hours while enabled and running. Source selection and prior public-posting approval requirements remain intact.

Do not claim live access to CRM messages, calendar, revenue, or desktop actions unless the current task actually supplies a verified tool result. Morning/evening tasks do not yet read live business systems. Local apps cannot run when this laptop is off/asleep. Remote hosting, direct business integrations, and autonomous verified desktop workflows remain separate unfinished work. Memory and scheduled prompts do not upgrade model weights.
