# ForgeMind staged evolution curriculum

Build capabilities in dependency order. Complete and verify one stage before the next.

## Stage 1 — trustworthy execution

- deterministic distinction between chat and action requests;
- typed action records and truthful tool-result reporting;
- bounded model context and cancellable operations;
- normalized blocker detection, audit reports, and rollback.

## Stage 2 — coding intelligence

- repository map for modules, symbols, imports, tests, and dependencies;
- isolated candidate workspaces and unified differences;
- project-specific test discovery;
- artifact delivery and validation.

## Stage 3 — knowledge quality

- structured facts with source, timestamp, confidence, and corrections;
- duplicate and contradiction detection;
- retrieval evaluations using fixed questions;
- automatic stale-source review without deleting history.

## Stage 4 — multimodal input

- multiple-file attachments and document adapters;
- local voice-to-text with review-before-send;
- optional OCR or vision adapter for images;
- clear capability detection when a model or dependency is unavailable.

## Stage 5 — authorized connections

- GitHub repository operations;
- Google Drive file discovery and export;
- additional applications through independent OAuth or API connectors;
- credential storage, revocation, audit records, and rate-limit handling.

## Stage 6 — durable autonomy

- persistent objective backlog;
- schedules or event triggers;
- per-objective budgets and cancellation;
- benchmark comparison before installation;
- owner-visible dashboard of attempts, blockers, installed capabilities, and rollback points.

Suggested first measurable objectives:

1. Show attempt number, elapsed time, phase, and last blocker during evolution.
2. Build a Python repository map and verify it against the CodeAtlas sample.
3. Add a controlled artifact workspace and return verified generated files.
4. Add local voice transcription behind an optional dependency and deterministic fixture tests.
5. Add a connector interface before implementing any additional service.
